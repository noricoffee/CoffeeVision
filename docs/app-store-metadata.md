## 3. 説明文（Description）

> 最大 4000 字。改行・箇条書き可（Markdown 記法は不可、プレーンテキスト）。

```
CoffeeVision は、コーヒーが好きな人のための「1 杯ごとのコーヒー記録帳」です。
カフェで飲んだ 1 杯も、自宅で淹れた 1 杯も、それぞれ 1 件の記録として残せます。記録が増えるほど、自分の好みの傾向が見えてきます。

【主な機能】

■ 1 杯ずつ、細かく残す
・コーヒー名と抽出方法（エスプレッソ／ハンドドリップ／フレンチプレスなど）
・産地・品種・精製方法・焙煎度・カップ
・0.5 刻みの星評価（ハーフスター対応）と自由メモ
・甘味・ボディ・酸味・風味・後味の 5 要素テイスティング
・「ラテアート」「浅煎り」など自由なタグ
・写真を添付して見た目も記録

■ カフェと一緒に記録する
・店名やキーワードでカフェを検索（Google Places）
・マップの「このエリアを検索」で表示範囲のカフェを一括表示
・カフェに紐付けない自宅・セルフ抽出の記録もOK

■ マップで振り返る
・記録のあるカフェをマップ上のピンで一覧
・同じカフェで飲んだ過去の記録をまとめて確認
・タグや好みでピンを絞り込み

■ 好みを分析する
・杯数・産地・焙煎度・抽出方法・評価の統計をグラフで表示
・Apple Intelligence 対応端末では、記録からあなたの傾向を要約したり、「好きな産地は？」といった質問に答えたりできます（処理はすべて端末内で完結します）

■ 安心して使える
・ライト／ダーク／システムのテーマ切り替え
・オフラインでも記録の閲覧・追加が可能
・記録はクラウドに自動でバックアップ（写真は端末内に保存）

「あのお店のあの一杯」も「今朝の一杯」も、ちゃんと残しておきたい——そんなあなたのためのアプリです。
```

> 写真の扱い（端末ローカル保存 / クラウド非同期）は §6 プライバシーと整合させること。「クラウドに自動でバックアップ」は記録テキスト（Firestore）を指し、写真は含まない旨を誤解させない表現にしている。

## 5. スクリーンショット計画

> 6.9 インチ（iPhone 16 Pro Max 等、必須）と 6.5 インチの 2 サイズを用意。1 サイズあたり最大 10 枚、最低 1 枚。シミュレータの該当機種でキャプチャする。

| # | 画面 | 訴求ポイント | キャプション案 |
|---|------|------------|--------------|
| 1 | マップ画面 | 記録済みカフェのピン + 埋め込み検索バー / エリア検索 | 「行ったお店も、これから行くお店も。」 |
| 2 | コーヒー記録詳細画面 | 評価・テイスティング・写真・タグが一画面に | 「あの一杯を、まるごと記録。」 |
| 3 | コーヒー記録 作成 / 編集画面 | 抽出方法・焙煎度・テイスティングまで細かく残せる | 「抽出も焙煎も、こだわりを残せる。」 |
| 4 | コーヒー記録一覧画面 | 時系列の振り返り（+ FAB からすぐ記録） | 「コーヒー巡りの軌跡が、ここに。」 |
| 5 | 分析画面 | 統計グラフ + 傾向の要約 | 「記録が増えるほど、好みが見えてくる。」 |
| 6 | カフェ詳細画面 | 同じカフェで飲んだ記録の集約 + 営業時間等 | 「お気に入りのお店を、何度でも。」 |

> キャプチャ前にデモ用のサンプル記録を投入しておく（空状態のスクショは避ける）。共有 Scheme「iosApp (Dummy Data)」でダミー `CoffeeRecord` 30 件をローカル DB に投入できる。
> 分析画面（#5）の Foundation Models 要約は Apple Intelligence 有効な実機でのみ表示される点に注意（シミュレータ撮影なら統計グラフのみになる）。
> ステータスバーは時刻 9:41 / フル電池に整える（`xcrun simctl status_bar` で設定可）。

## 6. プライバシー（App Privacy / 栄養表示ラベル）

App Store Connect の「App のプライバシー」セクションで申告する内容。実装事実に基づく。

### 6.1 収集するデータ

| データ種別 | 収集 | 用途 | ユーザーに紐付け | トラッキング | 備考 |
|-----------|------|------|----------------|------------|------|
| 位置情報（おおよそ / 正確） | する | アプリ機能（周辺カフェ検索） | 紐付けない | しない | `NSLocationWhenInUseUsageDescription`。検索時のみ取得、保存・送信は座標を Google Places に渡すのみ |
| 写真 | する（端末内） | アプリ機能（コーヒー記録への添付） | — | しない | 端末ローカル（Documents 配下）保存のみ。**サーバ送信なし**。App Privacy 上は「デバイスから持ち出さないデータ」に該当 → 申告不要の可能性が高いが、保守的に記載 |
| ユーザーコンテンツ（コーヒー記録: 評価 / テイスティング / メモ / タグ / カフェ情報） | する | アプリ機能（クラウド同期 / バックアップ）+ **同意時のみ** サービス改善のための分析 | 紐付ける | しない | Firestore に保存。匿名 uid に紐付く。サービス改善利用は初回オンボーディング / 設定の同意トグル（`analyticsConsent`、既定 false）にオプトインした場合のみ |
| 識別子（匿名ユーザー ID） | する | アプリ機能（同期のためのアカウント識別） | 紐付ける | しない | Firebase 匿名認証の uid |
| メールアドレス | する（任意。Apple でサインイン時のみ） | アプリ機能（アカウントのアップグレード / 引き継ぎ） | 紐付ける | しない | Sign in with Apple での匿名アカウントアップグレード時に Firebase Auth が保持。ユーザーは Apple の「メールを非公開」を選択可。**申告要否はリリース前に再確認** |

> 分析タブの AI 機能（傾向要約・Q&A・好み検索）は Apple の Foundation Models による**オンデバイス処理**で、記録データを外部サーバに送信しない（App Privacy の申告対象にならない）。

### 6.2 トラッキング

- **App Tracking Transparency（ATT）**: 不要。広告 SDK・サードパーティ解析でのクロスアプリ追跡を行わないため。
- サードパーティとのデータ共有: Google Places API へ検索クエリ / 座標を送信（カフェ検索機能の実現に必要な範囲のみ）。Firebase（Google）にユーザーコンテンツを保存。

### 6.3 第三者 SDK

| SDK | 提供元 | 用途 | 送信データ |
|-----|--------|------|-----------|
| Firebase Auth | Google | 匿名認証 + Sign in with Apple 連携 | 匿名 uid（Apple サインイン時は Apple ID 連携情報・メールアドレス） |
| Firebase Firestore | Google | 記録の同期 / バックアップ | コーヒー記録（評価 / テイスティング / メモ / タグ / カフェ情報スナップショット / 写真メタデータ）+ データ利用同意フラグ |
| Google Places API | Google | カフェ検索・エリア検索・詳細・写真取得 | 検索クエリ / 現在地・マップ中心座標 |

> Firebase Analytics / Crashlytics は導入していない（導入する場合は本表とプライバシー申告を更新すること）。

### 6.4 必要 URL

| 項目 | URL | 状態 |
|------|-----|------|
| プライバシーポリシー URL | （未作成） | **要作成・必須**。位置情報 / Firebase / Places の利用を記載 |
| サポート URL | （未作成） | **必須**。問い合わせ先（メール or 簡易ページ） |
| マーケティング URL | （任意） | 未定 |

> ⚠️ プライバシーポリシー URL とサポート URL は App Store 申請の必須項目。リリース前に用意が必要（GitHub Pages 等で可）。

## 8. App Review に関する情報（Review Notes）

審査担当者向けの補足。匿名認証のため通常のログインデモは不要だが、挙動を明記しておく。

```
・本アプリは起動時に Firebase の匿名認証で自動的にアカウントを作成します。ログイン不要でそのまま利用できます。
・設定タブから「Apple でサインイン」で匿名アカウントをアップグレードできます（任意）。アカウント削除も設定タブから可能で、Apple 連携アカウントの削除時には Apple トークンの失効（revoke）を行います（ガイドライン 5.1.1(v) 対応）。
・初回起動時に、記録データをサービス改善に利用することへの同意を確認するオンボーディングを表示します（任意。設定からいつでも変更可能）。
・カフェ検索・エリア検索には Google Places API を使用します。検索結果の表示には通信が必要です。位置情報は検索時のみ使用し、常時取得はしません。
・分析タブの AI 機能（傾向要約・Q&A）は Apple Intelligence 有効端末でのみ表示されます。非対応環境では統計グラフのみ表示されます（AI 処理はすべて端末内で完結し、外部送信はありません）。
・写真は端末内にのみ保存され、サーバーには送信されません。
・デモ用アカウント: 不要（匿名認証のため）
```

| 項目 | 値 |
|------|----|
| 連絡先（氏名 / 電話 / メール） | （要記入） |
| デモアカウント | 不要（匿名認証） |
| 添付（任意） | 主要画面のメモ等あれば |

## 10. 提出前チェックリスト

リリース直前に上から順に確認する。

### 確定が必要な原稿系（ユーザー判断）
- [ ] サブタイトル文言の確定
- [ ] プライマリ / セカンダリカテゴリの確定
- [ ] 説明文・キーワードの最終レビュー（キーワードは 100 字以内を再確認）

### 必須の外部準備
- [ ] プライバシーポリシー URL の作成・公開
- [ ] サポート URL の作成・公開
- [ ] App Review 連絡先情報の記入
- [ ] スクリーンショット（6.9" / 6.5" 各サイズ）の撮影・最終枚数決定

### App Store Connect 設定
- [ ] App のプライバシー（§6）を申告
- [ ] 年齢制限アンケート（§7）を回答
- [ ] 価格・配信地域の設定（無料 / 配信国）
- [ ] 輸出コンプライアンス（暗号化）: HTTPS 標準利用のみ → 「該当する暗号化を含むが免除対象」を選択想定。要確認

### ビルド / 技術
- [ ] `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` が App Store Connect のバージョンと一致
- [ ] リリースビルドで Places API キーが正しく注入される（`Secrets.xcconfig` の Release 設定）
- [ ] `GoogleService-Info.plist`（本番 Firebase プロジェクト）が同梱されている
- [ ] Firestore Security Rules が本番にデプロイ済
- [ ] Sign in with Apple の revoke 用 OAuth コードフロー設定（Services ID / Team ID / Key ID / 秘密鍵）を Firebase Console に登録済（フェーズ 5.2 参照。未設定だとアカウント削除がエラーになる）
- [ ] App Icon（light / dark / tinted）が全サイズ揃っている
- [ ] アーカイブ（Archive）→ App Store Connect へアップロード成功

> 輸出コンプライアンスは、通信が標準的な HTTPS のみであれば `ITSAppUsesNonExemptEncryption = NO` を Info.plist に設定して申告を簡略化できる。要否はリリース時に確認。
