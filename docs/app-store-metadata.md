## 3. 説明文（Description）

> 最大 4000 字。改行・箇条書き可（Markdown 記法は不可、プレーンテキスト）。

```
CoffeeVision は、カフェ巡りが好きな人のための「コーヒー体験記録帳」です。
訪れたカフェ・飲んだコーヒー・食べたフードを、ひとつの「訪問（Visit）」としてまとめて記録できます。後から見返せば、自分だけのコーヒー巡りの軌跡になります。

【主な機能】

■ カフェを探して記録する
・店名やキーワードでカフェを検索（Google Places）
・現在地周辺のカフェをマップとリストから探す
・気になったカフェをその場で訪問記録に追加

■ コーヒーを細かく残す
・抽出方法（エスプレッソ／ハンドドリップ／フレンチプレスなど）
・産地・品種・精製方法・焙煎度
・5段階の星評価と自由メモ
・1回の訪問に複数杯のコーヒーを記録可能

■ フードも一緒に
・一緒に食べたスイーツや軽食を評価とメモ付きで記録

■ 写真とメモで振り返る
・お店やコーヒーの写真を訪問記録に添付
・店内の雰囲気やお気に入りポイントをメモ

■ マップで振り返る
・訪問済みのカフェをマップ上のピンで一覧
・同じカフェへの過去の訪問をまとめて確認

■ 安心して使える
・ライト／ダーク／システムのテーマ切り替え
・オフラインでも記録の閲覧・追加が可能
・記録はクラウドに自動でバックアップ（写真は端末内に保存）

コーヒーが好きで、「あのお店のあの一杯」をちゃんと残しておきたい——そんなあなたのためのアプリです。
```

> 写真の扱い（端末ローカル保存 / クラウド非同期）は §6 プライバシーと整合させること。「クラウドに自動でバックアップ」は記録テキスト（Firestore）を指し、写真は含まない旨を誤解させない表現にしている。

## 5. スクリーンショット計画

> 6.9 インチ（iPhone 16 Pro Max 等、必須）と 6.5 インチの 2 サイズを用意。1 サイズあたり最大 10 枚、最低 1 枚。シミュレータの該当機種でキャプチャする。

| # | 画面 | 訴求ポイント | キャプション案 |
|---|------|------------|--------------|
| 1 | マップ画面 | 訪問済みカフェのピンと周辺カフェを一望 | 「行ったお店も、これから行くお店も。」 |
| 2 | Visit 詳細画面 | コーヒー・フード・写真・評価が一画面に | 「あの一杯を、まるごと記録。」 |
| 3 | カフェ検索画面 | テキスト / 現在地検索の結果リスト | 「次のカフェを、すぐ見つける。」 |
| 4 | Visit 作成 / 編集画面（コーヒー入力） | 抽出方法・焙煎度など細かく残せる | 「抽出も焙煎も、こだわりを残せる。」 |
| 5 | Visit 一覧画面 | 時系列の振り返り | 「コーヒー巡りの軌跡が、ここに。」 |
| 6 | カフェ詳細画面 | 同じカフェへの過去訪問の集約 | 「お気に入りのお店を、何度でも。」 |

> キャプチャ前にデモ用のサンプル Visit を数件投入しておく（空状態のスクショは避ける）。
> ステータスバーは時刻 9:41 / フル電池に整える（`xcrun simctl status_bar` で設定可）。

## 6. プライバシー（App Privacy / 栄養表示ラベル）

App Store Connect の「App のプライバシー」セクションで申告する内容。実装事実に基づく。

### 6.1 収集するデータ

| データ種別 | 収集 | 用途 | ユーザーに紐付け | トラッキング | 備考 |
|-----------|------|------|----------------|------------|------|
| 位置情報（おおよそ / 正確） | する | アプリ機能（周辺カフェ検索） | 紐付けない | しない | `NSLocationWhenInUseUsageDescription`。検索時のみ取得、保存・送信は座標を Google Places に渡すのみ |
| 写真 | する（端末内） | アプリ機能（訪問記録への添付） | — | しない | 端末ローカル（Documents 配下）保存のみ。**サーバ送信なし**。App Privacy 上は「デバイスから持ち出さないデータ」に該当 → 申告不要の可能性が高いが、保守的に記載 |
| ユーザーコンテンツ（メモ / 評価 / カフェ記録） | する | アプリ機能（クラウド同期 / バックアップ） | 紐付ける | しない | Firestore に保存。匿名 uid に紐付く |
| 識別子（匿名ユーザー ID） | する | アプリ機能（同期のためのアカウント識別） | 紐付ける | しない | Firebase 匿名認証の uid。氏名・メール等の個人情報は収集しない |

### 6.2 トラッキング

- **App Tracking Transparency（ATT）**: 不要。広告 SDK・サードパーティ解析でのクロスアプリ追跡を行わないため。
- サードパーティとのデータ共有: Google Places API へ検索クエリ / 座標を送信（カフェ検索機能の実現に必要な範囲のみ）。Firebase（Google）にユーザーコンテンツを保存。

### 6.3 第三者 SDK

| SDK | 提供元 | 用途 | 送信データ |
|-----|--------|------|-----------|
| Firebase Auth | Google | 匿名認証 | 匿名 uid |
| Firebase Firestore | Google | 記録の同期 / バックアップ | Visit / Coffee / Food / メモ / 評価 |
| Google Places API | Google | カフェ検索・詳細・写真取得 | 検索クエリ / 現在地座標 |

> Firebase Analytics / Crashlytics は導入していない（導入する場合は本表とプライバシー申告を更新すること）。

### 6.4 必要 URL

| 項目 | URL | 状態 |
|------|-----|------|
| プライバシーポリシー URL | （未作成） | **要作成・必須**。位置情報 / Firebase / Places の利用を記載 |
| サポート URL | （未作成） | **必須**。問い合わせ先（メール or 簡易ページ） |
| マーケティング URL | （任意） | 未定 |

> ⚠️ プライバシーポリシー URL とサポート URL は App Store 申請の必須項目。リリース前に用意が必要（GitHub Pages 等で可）。

## 8. App Review に関する情報（Review Notes）

審査担当者向けの補足。匿名認証のため通常のログインデモは不要だが、挙動を明記しておく。

```
・本アプリは起動時に Firebase の匿名認証で自動的にアカウントを作成します。ログイン画面はありません（サインインアップグレードは本バージョン未実装）。
・カフェ検索および周辺検索には Google Places API を使用します。検索結果の表示には通信が必要です。
・「現在地周辺のカフェ検索」を試す場合は、位置情報の許可と、シミュレータ/端末での位置設定をお願いします。位置情報は検索時のみ使用し、常時取得はしません。
・写真は端末内にのみ保存され、サーバーには送信されません。
・デモ用アカウント: 不要（匿名認証のため）
```

| 項目 | 値 |
|------|----|
| 連絡先（氏名 / 電話 / メール） | （要記入） |
| デモアカウント | 不要（匿名認証） |
| 添付（任意） | 主要画面のメモ等あれば |

## 10. 提出前チェックリスト

リリース直前に上から順に確認する。

### 確定が必要な原稿系（ユーザー判断）
- [ ] サブタイトル文言の確定
- [ ] プライマリ / セカンダリカテゴリの確定
- [ ] 説明文・キーワードの最終レビュー（キーワードは 100 字以内を再確認）

### 必須の外部準備
- [ ] プライバシーポリシー URL の作成・公開
- [ ] サポート URL の作成・公開
- [ ] App Review 連絡先情報の記入
- [ ] スクリーンショット（6.9" / 6.5" 各サイズ）の撮影・最終枚数決定

### App Store Connect 設定
- [ ] App のプライバシー（§6）を申告
- [ ] 年齢制限アンケート（§7）を回答
- [ ] 価格・配信地域の設定（無料 / 配信国）
- [ ] 輸出コンプライアンス（暗号化）: HTTPS 標準利用のみ → 「該当する暗号化を含むが免除対象」を選択想定。要確認

### ビルド / 技術
- [ ] `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` が App Store Connect のバージョンと一致
- [ ] リリースビルドで Places API キーが正しく注入される（`Secrets.xcconfig` の Release 設定）
- [ ] `GoogleService-Info.plist`（本番 Firebase プロジェクト）が同梱されている
- [ ] Firestore Security Rules が本番にデプロイ済
- [ ] App Icon（light / dark / tinted）が全サイズ揃っている
- [ ] アーカイブ（Archive）→ App Store Connect へアップロード成功

> 輸出コンプライアンスは、通信が標準的な HTTPS のみであれば `ITSAppUsesNonExemptEncryption = NO` を Info.plist に設定して申告を簡略化できる。要否はリリース時に確認。
