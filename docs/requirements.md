# CoffeeVision 要件定義

## アプリ概要

| 項目 | 内容 |
|------|------|
| アプリ名 | CoffeeVision |
| プラットフォーム | iOS（リリース対象）/ Android（KMP 共通レイヤーの検証ターゲット、リリース対象外） |
| ターゲット OS | iOS 26 以上 / Android 16（API 36）以上 |
| ターゲットユーザー | カフェ巡りを趣味とし、訪問記録 / 飲んだコーヒーの情報を残したいユーザー |
| コンセプト | カフェでの体験（カフェ・コーヒー・フード）を 1 つの「Visit（訪問）」として記録し、後で見返したり振り返ったりできるアプリ |

### 2. Visit（訪問記録）管理

Visit とはカフェへの 1 回の訪問記録の単位。1 Visit には 0..N の CoffeeItem と 0..N の FoodItem が紐づく。

**Visit フィールド**

| フィールド | 型 | MVP | 備考 |
|----------|---|-----|------|
| カフェ情報 | `Cafe`（Places API 由来） | ◎ | place_id・名称・住所・座標・写真参照などをスナップショット保存 |
| 訪問日 | `LocalDate` | ◎ | デフォルトは今日 |
| 内装の雰囲気 | `String`（自由入力） + タグ候補 | ◎ | 「落ち着き」「広い」「写真映え」等のタグも将来検討 |
| 総合評価 | `Int`（1..5）または `Double`（0.5 刻み） | ◎ | UI は星 5 段階 |
| メモ | `String`（複数行） | ◎ | |
| 写真 | 複数の `Photo`（最大 N 枚） | ◎ | 端末ローカル（Documents 配下）に保存。iCloud Backup でバックアップ |
| CoffeeItem 一覧 | `List<CoffeeItem>` | ◎ | 1..N が一般的だが 0 件もあり得る |
| FoodItem 一覧 | `List<FoodItem>` | ◎ | 0 件もあり得る |

**Visit 機能**

| # | 機能 | 優先度 | 備考 |
|---|------|--------|------|
| 2-1 | Visit の新規作成（カフェ検索 → 詳細入力） | ◎ | Places API でカフェを検索 |
| 2-2 | Visit の編集 | ◎ | |
| 2-3 | Visit の削除 | ◎ | |
| 2-4 | Visit 一覧の表示（時系列） | ◎ | 最新順 |
| 2-5 | Visit 詳細の表示 | ◎ | |
| 2-6 | お気に入り Visit のピン留め | ○ | |
| 2-7 | カフェ別の Visit 集約表示 | ○ | 同一 place_id をまとめる |

### 9. 分析（コーヒー傾向分析）

これまで登録した `CoffeeRecord` 群を分析し、自分の好み・傾向を振り返るための機能。専用の「分析」タブとして提供する。分析は **3 階層** で構成する（詳細設計は [`implementation_note.md`](./implementation_note.md) 2026-06-19 分析機能エントリ / 集計モデルは [`data-model.md`](./data-model.md) §1.6）。

| 階層 | 内容 | 計算方法 | プラットフォーム |
|------|------|---------|----------------|
| 1. 記述統計 | 杯数 / 産地分布 / 焙煎度・抽出方法分布 / 平均評価 / 月次推移 / よく行く店 | KMP 共通層で決定論的に算出（`CoffeeStats`） | iOS / Android 共通（表示は iOS のみ） |
| 2. 傾向抽出 | 高評価群（rating ≥ 4.0）に共通する属性を最小サンプル数の閾値付きで抽出 | KMP 共通層でルールベース算出（`FavoriteSignals`） | 同上 |
| 3. 自然言語の解釈 | 階層1・2 の集計サマリを基に「あなたの傾向」を要約 / 対話 Q&A で応答 | iOS の Foundation Models（オンデバイス LLM） | **iOS 専用**（Android は分析タブ非表示） |

**設計原則**: 数値・分布は階層1・2 で**決定論的に正確に**算出し、その**集約済みサマリ（`CoffeeStats`）だけ**を階層3 の LLM に渡す。生レコードを LLM に流さない（正確性 / オンデバイス LLM のコンテキスト窓 / 再現性・テスト容易性のため）。

| # | 機能 | 優先度 | 備考 |
|---|------|--------|------|
| 9-1 | 記述統計の可視化（階層1） | ○ | 杯数・産地・焙煎度・抽出方法・平均評価・月次推移・よく行く店 |
| 9-2 | Foundation Models による傾向要約サマリ（階層3） | ○ | `CoffeeStats` を入力に 2–3 文で要約。Apple Intelligence 無効 / 非対応端末では階層1 のみ表示にフォールバック |
| 9-3 | 高評価群の傾向抽出（階層2） | △ | `FavoriteSignals`。サンプル数が閾値未満の信号は出さない |
| 9-4 | 対話 Q&A（階層3） | △ | 「一番高評価だった店は？」等。まず `CoffeeStats` を文脈注入する方式（ツール無し）、将来 tool calling へ拡張 |
| 9-5 | 好みのカフェをマップで探す | ✕（将来） | 要件外。分析結果とマップの連携は後続フェーズ |

> Foundation Models は **iOS 専用**のため、Android（KMP 検証ターゲット）では分析タブ自体を表示しない。階層1・2 の集計（`CoffeeStats` / `BuildCoffeeStatsUseCase`）は KMP 共通層に置き、両 OS でビルド・テスト可能とする。

## 非機能要件

| 項目 | 要件 |
|------|------|
| パフォーマンス | 一覧表示は 60fps を維持する。画像はサムネイルキャッシュで遅延読み込み |
| アクセシビリティ | VoiceOver 対応・Dynamic Type 対応・最小タップ領域 44pt |
| オフライン | 完全オフライン動作可能（Firestore のオフライン永続化、ローカル SQLDelight） |
| 同期 | オンライン復帰時に Firestore が自動で同期する。独自の同期キューは持たない |
| データ保存 | ローカル: SQLDelight + 写真ファイル（Documents 配下） / クラウド: Firestore（写真本体は対象外） |
| セキュリティ | Firestore Security Rules で `uid` に基づくアクセス制御。API キーは難読化 |
| プライバシー | 位置情報の利用は Places 検索時のみ。常時取得しない |
| API キー管理 | `local.properties` から `BuildConfig` 経由で注入。リポジトリにコミットしない |

## 画面一覧

ルートは TabBar 構成（iOS 26 の `TabView` 新 API）。3 タブで構成され、`role: .search` の検索タブは右端固定。

| 画面名 | 配置 | 説明 | 対応機能 |
|--------|------|------|---------|
| スプラッシュ画面 | ルート前 | 起動時のローディング | - |
| マップ画面 | Tab 1（左） | 訪問済みカフェのピンと現在地周辺の Places ピンを色で区別して同時表示。フィルタトグルで個別表示の切替が可能。Apple Maps が標準表示する POI（カフェ / レストラン / ベーカリー）のタップで Google Places に照合してカフェ詳細に進める | 2-4, 2-7, 5-1, 5-2, 5-3 |
| Visit 一覧画面 | Tab 2（中） | 直近の Visit 一覧（時系列）。新規追加導線はここには持たない | 2-4 |
| カフェ検索画面 | Tab 3（右、`role: .search`） | テキスト検索・現在地周辺検索の結果リスト | 5-1, 5-2, 5-3 |
| カフェ詳細画面 | Tab 1 / Tab 3 から push | カフェ情報（Places スナップショット）+ 同じカフェへの過去 Visit 一覧 + 「+ Visit を追加」ボタン。要件のカフェ別 Visit 一覧をここに統合 | 2-7 |
| Visit 詳細画面 | Tab 2 から push | Visit の全フィールド・CoffeeItem / FoodItem 一覧・写真表示 | 2-5 |
| Visit 作成 / 編集画面 | カフェ詳細から sheet | 評価 / 写真 / メモ → CoffeeItem / FoodItem を追加。新規作成はカフェ詳細の「+ Visit を追加」起点に一本化 | 2-1, 2-2, 3-1, 4-1, 5-1, 5-2 |
| 分析画面 | Tab（iOS 専用） | コーヒー記録の記述統計（グラフ）+ Foundation Models による傾向要約。将来は対話 Q&A | 9-1, 9-2, 9-3, 9-4 |
| 設定画面 | 別途検討 | アプリ設定・アカウント管理 | 8-x |

## データモデル概要

| エンティティ | 説明 | 関連 |
|-------------|------|------|
| `Visit` | 1 回のカフェ訪問 | `Cafe`（埋め込み）/ `Photo`（多）/ `CoffeeItem`（多）/ `FoodItem`（多） |
| `Cafe` | Places API 由来のカフェ情報スナップショット | `place_id` をキーに集約可能 |
| `CoffeeItem` | 1 杯のコーヒー記録 | `Visit` に従属 |
| `FoodItem` | フード記録 | `Visit` に従属 |
| `Photo` | 写真への参照 | Documents 配下からの相対ファイル名（クラウド同期対象外） |

詳細なフィールド定義・SQLDelight / Firestore スキーマは [`data-model.md`](./data-model.md) を参照。
