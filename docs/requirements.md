# CoffeeVision 要件定義

**1.0 リリース時点（2026-08-21）の仕様。** 各機能の実装状態を「1.0 に入っているか」で示す。それ以前の要件の変遷は git log と [`tasks-archive.md`](./tasks-archive.md) を参照。

## アプリ概要

| 項目 | 内容 |
|------|------|
| アプリ名 | CoffeeVision |
| プラットフォーム | iOS（リリース対象）/ Android（KMP 共通レイヤーの検証ターゲット、リリース対象外） |
| ターゲット OS | iOS 26 以上 / Android 16（API 36）以上 |
| ターゲットユーザー | カフェ巡り / コーヒーを趣味とし、飲んだ 1 杯ごとの情報を残して振り返りたいユーザー |

### 2. CoffeeRecord（コーヒー記録）管理

CoffeeRecord は **1 杯のコーヒー = 1 件の記録**を表すアプリの中心エンティティ。カフェで飲んだ 1 杯にも、自宅などでのセルフ抽出にも対応する（カフェ情報は任意）。

**CoffeeRecord フィールド**

| フィールド | 型 | 1.0 | 備考 |
|----------|---|-----|------|
| カフェ情報 | `Cafe?`（Places API 由来） | 1.0 | place_id・名称・住所・座標・写真参照などをスナップショット保存。**null = セルフ抽出（自宅等）** |
| 飲んだ日 | `LocalDate` | 1.0 | デフォルトは今日 |
| 総合評価 | `Double?`（0.5 刻み、0.5..5.0） | 1.0 | UI は星 5 段階（ハーフ対応）。**`null` = 未評価**（集計から除外）。**未評価のまま保存可**（「まず記録、あとで評価」） |
| メモ | `String`（複数行） | 1.0 | 風味・所感・フード・内装の雰囲気などを自由記述 |
| 写真 | 複数の `Photo` | 1.0 | 端末ローカル（Documents 配下）に保存。iCloud Backup でバックアップ。**1 記録あたり最大 10 枚**、保存時に**長辺 2048px / JPEG q0.8 へ縮小**（用途の最大解像度が共有カード 1080×1350px であること、全画面表示 6.7 インチ @3x = 1290px に余裕があることが根拠） |
| コーヒー名 | `String` | 1.0 | 「本日のコーヒー」「エチオピア イルガチェフェ」など（必須） |
| 抽出方法 | `enum BrewMethod` | 1.0 | エスプレッソ / ハンドドリップ / ネルドリップ / フレンチプレス / エアロプレス / サイフォン / コールドブリュー / その他 |
| 産地 | `String?`（国名） | 1.0 | **国ドロップダウン選択**（`CoffeeOriginCatalog` = コーヒー生産国 ~43 か国 + 「ブレンド」/「その他」、生産量ランキング順）。「その他」は国名の自由入力欄を出す。詳細 [`data-model.md`](./data-model.md) §1.3a |
| エリア | `String?`（自由入力） | 1.0 | 農園 / 生産地域（例「イルガチェフェ」「ウエウエテナンゴ」）。表示専用で分析には使わない |
| 品種 | `String?`（自由入力 + 推奨候補） | 1.0 | ティピカ / ブルボン / ゲイシャ / SL28 等 |
| 精製方法 | `enum ProcessingMethod?` | 1.0 | ナチュラル / ウォッシュト / ハニー / アナエロビック / その他 |
| 焙煎度 | `enum RoastLevel?` | 1.0 | ライト / シナモン / ミディアム / ハイ / シティ / フルシティ / フレンチ / イタリアン |
| カップ | `String?` | 1.0 | 使用されたカップの種類 / ブランド等のメモ |
| 抽出レシピ | `String?` | 1.0 | 豆量 / 湯量 / 湯温 / 抽出時間などのメモ（セルフ抽出向け・自由記述） |
| テイスティング | `TastingScores?`（甘味 / ボディ / 酸味 / 風味 / 後味、各 1..10） | 1.0 | Blue Bottle「Elements of Coffee Tasting」由来の 5 要素。強度スケール（UI はスライダー）。**任意だが、付ける場合は 5 要素すべて必須**（all-or-nothing）。`+` で 5 スライダーを一括表示。詳細は [`data-model.md`](./data-model.md) §1.1a |
| タグ | `List<String>` | 1.0 | ユーザー定義タグ（例: 「ラテアート」「浅煎り」） |

### 5. カフェ検索（Google Places API）

> **帰属表示の義務**: Places のコンテンツを **Google マップ以外**（本アプリは Apple MapKit + 自前 UI）に表示する場合、Google Maps ロゴ（スペースが限られる場合は「Google Maps」テキスト）の表示がポリシー上必須。さらに**写真は表示のたびに作者をクレジット**する必要がある（`Cafe.photoAttributions`、data-model §1.2）。App Store ガイドライン 5.2.2（サードパーティ規約の遵守）に直結し、審査より **Google 側の是正要求 → API キー停止**のほうがリスクが大きい。**Places データを新しい画面に出すときは帰属表示をセットで実装すること**。出典: [Places ポリシー](https://developers.google.com/maps/documentation/places/web-service/policies)
>
> 1.0 で帰属を出している面は 4 つ（カフェ詳細 / マップ検索結果シート / ピン選択カード / エディタのカフェ検索シート）+ 写真の作者バッジ。**出さない面**は記録一覧 / 記録詳細 / 共有カード / 保存済みリスト（いずれも保存済みスナップショットの表示なので対象外）。小サムネイルの作者帰属は「より大きな版で完全な帰属にアクセスできれば省略可」の条項で省略している。

| # | 機能 | 1.0 | 備考 |
|---|------|-----|------|
| 5-1 | テキスト検索（店名 / キーワード） | 1.0 | Places API Text Search。業態を寄せる補完語は「 コーヒー」 |
| 5-2 | 現在地周辺のカフェ検索 | 1.0 | Nearby Search、`includedPrimaryTypes = [cafe, coffee_shop]` |
| 5-3 | カフェ詳細（住所・写真・営業時間） | 1.0 | Place Details。写真は初期 3 枚 + 「さらに表示」で 3 枚ずつ、上限 10 枚の段階読み込み |
| 5-4 | カフェのスナップショットを CoffeeRecord に紐付けて保存 | 1.0 | Places API 規約に従い、画像 URL は逐次再取得。セルフ抽出記録は紐付けなし（`cafe = null`） |
| 5-5 | 表示範囲のカフェをマップにピン一括表示（「このエリアを検索」） | 1.0 | 地図をパン/ズーム後に出るボタンで表示範囲（中心 + 半径）を検索し候補を全ピン表示。**検索バーにキーワードがあればそのキーワード + 表示範囲の位置バイアスで再検索（`searchText`）、空なら周辺一括検索（`searchNearby`）**。エリア検索の結果は**検索実行時の表示範囲（可視領域の矩形）内に限定**する（iOS クライアント側フィルタ。`locationBias` は範囲制限でなく近傍ヒントのため範囲外が混入するのを除外）。Places API の 1 回最大 20 件が上限（範囲外分をクライアントで捨てるため範囲内表示は 20 件未満に減る場合あり）。テキスト検索結果は全件ピン + リスト併用（範囲フィルタ対象外） |
| 5-6 | 都道府県別おすすめカフェの常時強調表示（キュレーション） | 1.0 | サービス管理の Firestore `curatedCafes` を専用ピン（通常カフェピンと同アイコンの拡大 + `Color.orange` 高彩度 + ★バッジ = Google Maps 風 POI 強調）で**トグルなしで強調表示**。表示は Apple 周辺ピンと同じズームゲート（可視半径 3000m 以内）でズームイン時のみ。タップで placeId 直渡しのカフェ詳細へ（Details 1 回で解決）。一覧シート・チップは作らない。**1.0 の収録は 9 県 421 件**（東京 / 大阪 / 京都 / 神奈川 / 愛知 / 福岡 / 北海道 / 千葉 / 埼玉）。選定基準は評価 4.4・レビュー 100 件以上の上位 + 人気枠（評価 3.7 以上 & レビュー 500 件以上を枠外で全件）、`coffee_shop` タイプ厳格化 + 大手チェーンの名前除外。47 県フル展開はしない（地方は基準を満たす店が 30 件に満たずチェーンで埋まる + リフレッシュコストが県数に線形）。詳細は [`data-model.md`](./data-model.md) §1.10 |

### 9. 分析（コーヒー傾向分析）

これまで登録した `CoffeeRecord` 群を分析し、自分の好み・傾向を振り返るための機能。専用の「分析」タブとして提供する。分析は **3 階層** で構成する（集計モデルは [`analysis-model.md`](./analysis-model.md) §1）。

| 階層 | 内容 | 計算方法 | プラットフォーム |
|------|------|---------|----------------|
| 1. 記述統計 | 杯数 / 産地分布 / 焙煎度・抽出方法分布 / 平均評価 / 月次推移 / よく行く店 | KMP 共通層で決定論的に算出（`CoffeeStats`） | iOS / Android 共通（表示は iOS のみ） |
| 2. 傾向抽出 | 高評価群（rating ≥ 4.0）に共通する属性を最小サンプル数の閾値付きで抽出 | KMP 共通層でルールベース算出（`FavoriteSignals`） | 同上 |
| 3. 自然言語の解釈 | 階層1・2 の集計サマリを基に「あなたの傾向」を要約 / 対話 Q&A で応答 | iOS の Foundation Models（オンデバイス LLM） | **iOS 専用**（Android は分析タブ非表示） |

**設計原則**: 数値・分布は階層1・2 で**決定論的に正確に**算出し、その**集約済みサマリ（`CoffeeStats`）だけ**を階層3 の LLM に渡す。生レコードを LLM に流さない（正確性 / オンデバイス LLM のコンテキスト窓 / 再現性・テスト容易性のため）。

| # | 機能 | 1.0 | 備考 |
|---|------|-----|------|

### 11. 広告（AdMob アダプティブバナー）

収益化手段として Google Mobile Ads SDK（AdMob）の**アダプティブバナー広告**を表示する。Places API を主とする従量コストの回収が目的。

**アーキテクチャ上の位置づけ**: 広告は表示の関心事として **`iosApp` の View 層で完結**させ、KMP 共通層・ViewModel には広告の概念を持ち込まない。Android（KMP 検証ターゲット、リリース対象外）には導入しない。「広告非表示」IAP は**見据えない**（必要になった時点で後付けする）。

| # | 機能 | 1.0 | 備考 |
|---|------|-----|------|
| 11-1 | カフェ詳細のインライン広告 | 1.0 | 情報系セクション（カフェ情報 / 外部リンク / 営業時間）の後・コーヒー記録セクションの直前に 1 枠。**インラインアダプティブバナー**（maxHeight 制限付き） |
| 11-2 | マップ検索結果シートのインライン広告 | 1.0 | 検索結果シート（下部ドラッグシート）内の 3 件目の後に 1 枠。**結果 3 件未満のときは非表示**（広告が結果を支配するのを避ける）。シートの fold 下に置かれるため、シートのルート `VStack` から先読みロードする（枠自身の `.task` は発火しない） |
| 11-4 | ATT 許可フロー（プレプロンプト付き） | 1.0 | データ利用同意オンボーディング直後に「広告により無料で提供している」旨の説明（プレプロンプト）→ ATT ダイアログ。拒否時は非パーソナライズ広告（NPA）にフォールバック。**未実施ユーザーは起動時（`bootstrap()` 完了時）に 1 回だけ到達させる**（`UserDefaults` フラグ方式。オンボーディング済みの既存ユーザーの取りこぼし防止） |

**確定仕様（全面共通）**:

- 広告は**カフェ詳細とマップ検索の 2 面のみ**。**記録タブ・分析タブには置かない** — 定着の核となる記録・振り返り画面のバナーは、定着が命の初期にリテンションを削る割に収益が小さいため（実装・表示確認まで完了した状態から撤去した判断。再導入するならこの前提から検討し直すこと）
- ロード失敗・オフライン時は**枠ごと畳む**（プレースホルダなし。補助機能の失敗は無音の既存方針と整合）
- クライアント側の自動リフレッシュ実装はしない（バナーの自動更新は AdMob コンソールのユニット設定に委ねる）
- `maxAdContentRating = G`（全年齢向けに制限）
- AdMob App ID / 広告ユニット ID（2 面 = 2 ユニット）は Places キーと同じ経路（`Secrets.xcconfig` → `Info.plist`）で注入。**リリースビルドは本番 ID 必須**（CI が未設定なら fail-fast。ローカル・日常検証はデモ ID にフォールバックさせ、本番 ID の自己タップによる無効トラフィックを避ける）
- 広告の帰属表示・AdChoices はバナーでは Google レンダリングに内蔵されるため自前実装なし
- 配信地域は**日本のみ** → GDPR 同意フォームは不要。**UMP のメッセージ表示 API はコードから呼ばない**（コンソール構成に挙動が依存し、ATT メッセージ構成時は GDPR 圏外でも自前プレプロンプトと二重表示になるため。UMP SDK 自体は Google Mobile Ads SDK の内部依存としてリンクされるのみ。EU 配信を始める場合は GDPR フォーム実装として再導入）
- **Places 由来のデータ（店名・カテゴリ等）を広告リクエストのターゲティングシグナルに渡さない**（Google Maps Platform 規約遵守）
- SKAdNetwork 識別子は Google 公式の 50 件を `Info.plist` に列挙（ATT 拒否ユーザーの広告成果計測 = fill 率・eCPM に効く）。一覧は随時更新されるため、リリース前に再取得する

|------|------|

| セキュリティ | Firestore Security Rules で `uid` に基づくアクセス制御。API キーは Google Cloud 側のキー制限で保護する。`Info.plist` / `BuildConfig` 内の値は平文（クライアント配布物である以上難読化に本質的意味はなく、キー制限で担保する方針）。**Places キーの防御は「予算アラート + クォータ上限 + API 制限の Places 限定」の 3 点セット**で、どれが欠けても請求の天井が成立しない（[`paid-services.md`](./paid-services.md) §1） |
| プライバシー | 位置情報の利用は Places 検索時のみ。常時取得しない |
| ローカライズ | UI は日本語のみ。バンドルの `CFBundleDevelopmentRegion` / `CFBundleLocalizations` は `ja`（`en` のみだと日本語端末でも `DatePicker` 等が英語表記になる）。`LocalDate ↔ Date` 変換は `Calendar(identifier: .gregorian)` 固定（`Calendar.current` は和暦端末で永続データを壊す） |
| 対応デバイス | iPhone のみ（`TARGETED_DEVICE_FAMILY = 1`）。iPad は対象外 |

## データモデル概要

| エンティティ | 説明 | 関連 |
|-------------|------|------|
| `CoffeeRecord` | 1 杯のコーヒー記録（中心エンティティ） | `Cafe?`（埋め込み・任意）/ `Photo`（多）/ `TastingScores?`（埋め込み・任意） |
| `Cafe` | Places API 由来のカフェ情報スナップショット | `placeId` をキーに集約可能（`VisitedCafe`） |
| `TastingScores` | テイスティング 5 要素（甘味 / ボディ / 酸味 / 風味 / 後味） | `CoffeeRecord` に埋め込み（all-or-nothing） |
| `Photo` | 写真への参照 | Documents 配下からの相対ファイル名（クラウド同期対象外） |
| `VisitedCafe` | 同一カフェの記録を集計した表示用モデル | `cafe != null` の `CoffeeRecord` を `placeId` で集約 |
| `BeanProfile` | サーバー管理の豆ナレッジ（産地 / 品種 / 精製 / フレーバー） | 好み傾向の言語化と未経験豆の提案に利用 |
| `SavedCafe` | 行きたい店（ウィッシュリスト）。§10 | `Cafe` を埋め込みスナップショット + 保存日時 + メモ。`placeId` が自然キー |
| `CuratedCafe` | サーバー管理の都道府県別おすすめカフェ。§5-6 | placeId + 名前 + 座標 + JIS 都道府県コードの最小限（Places 規約対応） |
| `AuthAccount` | アカウント情報 + データ利用同意 | `analyticsConsent` |

詳細なフィールド定義・SQLDelight / Firestore スキーマは [`data-model.md`](./data-model.md)、永続化しない派生集計（`CoffeeStats` / `FavoriteSignals` / `RecommendedCafe` / `UnexploredBeanSuggestion`）は [`analysis-model.md`](./analysis-model.md) を参照。
